# coding-pm — 项目同步管理 Skill

## 这是什么

一个项目全生命周期管理 skill，覆盖项目从开始到结束的四个关键阶段：**开工 → 同步一下 → 审计验收 → 收尾**。

名字 **coding-pm** 代表这个 skill 的本质——在代码和文档之间做桥梁。

## 怎么用

在你的项目目录下，直接对 AI 说关键词就能触发对应的阶段：

| 你说 | AI 做什么 |
|------|----------|
| **开工** | 扫描规则文档（有则用，无则逐条提问帮你创建 AGENTS.md）→ 检查/创建 app/design/docs 目录 → 报告就绪 |
| **同步一下** | 读代码 → 与现有文档对比 → 增量更新 docs/ 和 design/ui-components.html |
| **审计验收**（完整4字） | 检查文档与代码是否同步 → 不同步则中断报错 → 同步则逐项审计并出报告 |
| **收尾** | 全量重写 docs/ 和 design/ → 版本 v1.0 → 详细到可复现 |

## 管理的目录结构

```
项目根目录/
├── app/          ← 项目代码（前端、后端、配置文件等）
├── design/       ← UI/UX 设计文件（核心产出：ui-components.html）
└── docs/         ← 文档文件（PRD.md、SPEC.md、README.md）
```

## 四个阶段详解

### 🚀 开工 — 项目开始

1. **扫规则** — 找根目录下的规则文档（`.claude.md` → `CLAUDE.md` → `AGENTS.md` → `project-rules.md` → `.cursorrules`）
   - **找到了** → 告诉你用的是哪个，加载并遵守
   - **没找到** → **一次一个问题**问你：先了解你（角色、技术水平、沟通语言、核心原则、工作纪律、边界），再了解项目（项目描述、目标用户）。全部问完后在根目录创建 AGENTS.md（含关于你、核心原则、工作纪律、边界、项目信息章节），并严格遵守
2. **建目录** — 确保 app/、design/、docs/ 存在
3. **报就绪** — 通知你项目已准备好

### 🔄 同步一下 — 进行中同步

1. **读状态** — 读完所有代码和现有文档
2. **做对比** — 找出新增、修改、删除的差异
3. **更新 ui-components.html** — 创建/更新可视化的组件库页面（可以直接在浏览器打开看），把所有 UI/UX 细节写进去，标准是别人打开就能 1:1 复刻
4. **增量更新 docs/** — 新增的补上、修改的更新、已删除的标记🚫废弃并写明原因、没变的不动
5. **汇报** — 告诉你更新了什么

### 🔍 审计验收 — 项目审计

> ⚠️ 前置条件：文档必须与代码同步，不同步则不审计

1. **查同步** — 对比 docs/ 和 design/ui-components.html 是否与实际代码一致
2. **不同步则中断** — 汇报哪里不同步，建议先做「同步一下」
3. **同步则审计** — 覆盖 8 个维度（架构、技术栈、组件、API、用户流程、样式、SSE、交互/动效）
4. **每项5要素** — 规则来源、对应文件、验收方式、实际结果、是否通过
5. **出报告** — 在项目根目录生成 audit-report.md，含总览表格、逐项明细、问题清单、审计结论

### 🏁 收尾 — 项目结束

1. **全量读取** — 读完所有代码和设计
2. **全量重写 docs/** — PRD.md（含验收标准）、SPEC.md（架构/技术栈/用户流程，每项选型写原因）、README.md（项目说明书）
3. **全量重写 design/** — ui-components.html（v1.0 标准版）
4. **版本 v1.0**，详细到别人拿到就能原样复现
5. **汇报** — 告诉你产出了什么文件

## 重要原则

- **准确性优先** — 所有文档内容基于实际代码，不编造不猜测
- **尊重已有** — 开工不删改、同步只增量更新、收尾才全量重写
- **可复现性** — 收尾标准的底线：开发者拿到文档不需要再问问题
- **规则文档柔性** — 有规则就用，没规则就逐条问清楚后创建 AGENTS.md
